# Contributing

1. Read the skill contract and threat model before changing package fields or workflow semantics.
2. Keep workflows declarative; do not add executable code or implicit side effects.
3. Add positive and negative tests for every validator change.
4. Preserve strict JSON parsing, bounded inputs, and per-step policy metadata.
5. Update schemas, examples, capabilities, compatibility, and changelog together when interfaces change.
6. Do not claim authentication, authorization, execution, or runtime integration without independently reproducible evidence.
7. Do not add a license file until the portfolio-level licensing decision is approved.
